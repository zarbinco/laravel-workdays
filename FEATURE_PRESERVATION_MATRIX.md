Shared validation rejects shared malformed-input validation duplicate weekend aliases (for example `1` and `Monday` in the same list) and recurring holiday titles outside string/null. Both Config and Database reject the same candidates; `DatabasePublicationTest::test_config_and_database_publication_reject_the_same_malformed_shared_fields` is the exact paired regression. `test_missing_nondefault_persisted_profile_is_source_corruption_instead_of_a_bulk_item_error` and `test_malformed_persisted_integer_is_not_silently_coerced` add persistence-corruption protection. Valid numerical algorithms are unchanged.

## Provenance Allowlist, Retirements, And Remaining Work

Cross-driver tests compare concrete types, timestamp microseconds, eligibility, routing, windows, stage lists, calculations, and serialization. The exact allowed source differences are:

- `DayReason.source` / captured `days[*].holiday_reasons[*].source` for `custom_holiday` and `extra_working_day`: `config` versus `database`.
- Snapshot `calendar_evidence.profiles[*].holiday_inputs.recurring[calendar][key].source`, `holiday_inputs.custom[date].source`, and `holiday_inputs.extra[date].source`.
- Derived `calendar_version` and `integrity_hash` when the evidence includes those different labels.

Recurring reason source remains `holiday_provider`; weekend source remains `profile`. Administrative revision IDs are not attached to snapshot schema and do not change selected-calendar fingerprints. snapshot provenance checks named provenance paths and then compares every remaining payload field; it does not broadly strip evidence. Same-source standalone/Bulk comparisons mask nothing.

The supported schema consists of immutable revision/profile documents and an active pointer. Older partial-holiday models and tables are not a second supported source. Removing package files cannot delete published migrations or application tables; review any schema transition deliberately in a separate test environment. No automatic data conversion or cleanup is provided.

Applications own authorization, persistence of orders/events, queues, notifications, payments, capacity reservations, external dataset acquisition and revision retention. These responsibilities are outside the calculation APIs.

Every listed calculation family is implemented. Remaining verification limits concern unexecuted runtimes and remote CI, not unavailable Database features. Numerical schedule normalization does not mutate stored raw definitions.
