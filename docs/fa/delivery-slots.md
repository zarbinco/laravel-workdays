# بازه‌های تحویل و دریافت حضوری

[English](../en/delivery-slots.md) · [همه راهنماها](README.md)

از <code dir="ltr">deliverySlots()</code> برای پیشنهاد زمان‌هایی استفاده کنید که یک خدمت آماده است و در پنجره کاری جا می‌گیرد. این خروجی گزینه انتخاب است و ظرفیت رزرو نمی‌کند. پیش از تأیید مشتری، ظرفیت و هم‌زمانی رزرو را در برنامه کنترل کنید.

## ساخت دو گزینه

پس از آماده‌کردن [تقویم نمونه](getting-started.md)، لحظه آمادگی را صریح بدهید:

<!-- example: delivery-slots -->

<div dir="ltr">

```php
use Zarbinco\LaravelWorkdays\Facades\Workday;

$result = Workday::deliverySlots('2026-11-02T08:00:00Z', [
    'profile' => 'global',
    'timezone' => 'UTC',
    'days' => 1,
    'duration_minutes' => 60,
    'step_minutes' => 60,
]);
foreach ($result->slots as $slot) {
    echo $slot->startsAt->format('H:i'), '-', $slot->endsAt->format('H:i'), PHP_EOL;
}
```

</div>

<div dir="ltr">

```text
09:00-10:00
11:00-12:00
```

</div>

هر گزینه در یک پنجره کاری مستقل جا می‌گیرد؛ وقفه بین آن‌ها به مدت خدمت اضافه نمی‌شود. اگر آمادگی باید شامل کار انبار باشد، ابتدا [برنامه‌ای تا نقطه آمادگی](delivery.md) بسازید و <code dir="ltr">completedAt</code> مرحله مناسب یا پایان همان برنامه را ورودی بدهید. پایان برنامه تحویل کامل، الزاماً زمان آمادگی دریافت حضوری نیست.

## گزینه‌ها

| کلید | نوع و محدوده | پیش‌فرض |
|---|---|---|
| <code dir="ltr">profile</code> | نام پروفایل با ساعت کاری معتبر | الزامی |
| <code dir="ltr">timezone</code> | شناسه IANA تقویم خدمت | الزامی |
| <code dir="ltr">days</code> | صحیح ۱ تا ۳۱؛ شرط <code dir="ltr">days - 1 &lt;= max_scan_days</code> | الزامی |
| <code dir="ltr">duration_minutes</code> | صحیح ۱ تا ۱۴۳۹؛ دقیقه واقعی طول گزینه | الزامی |
| <code dir="ltr">step_minutes</code> | صحیح ۱ تا ۱۴۳۹؛ فاصله شروع گزینه‌ها | الزامی |
| <code dir="ltr">min_notice_minutes</code> | صحیح نامنفی قابل نمایش | صفر |
| <code dir="ltr">max_slots</code> | صحیح ۱ تا ۲۰۰ | ۵۰ |

مقدار عددی باید عدد صحیح PHP باشد؛ رشته عددی، اعشاری، بولی و null پذیرفته نیست. برای پیش‌فرض، کلید اختیاری را حذف کنید. گزینه ناشناخته یا تنظیم پروفایل نامعتبر، <code dir="ltr">WorkdayConfigurationException</code> می‌دهد.

فاصله اطلاع قبلی، یک بار به لحظه آمادگی روی خط زمانی UTC اضافه می‌شود؛ دقیقه سپری‌شده است و تعطیلی را هم شامل می‌شود، نه دقیقه کاری. اگر فاصله قابل نمایش باشد ولی از محدوده تاریخ‌ها بیرون برود، نتیجه خالی است. مدت غیرقابل نمایش خطا می‌دهد؛ سقف دلخواه دیگری برای آن تعریف نشده است.

## ترتیب شروع و مرزها

شروع‌ها از ساعت بازشدن **هر پنجره** با گام مشخص ساخته می‌شوند. آمادگی فقط شروع‌های زودتر را حذف می‌کند و شبکه شروع‌ها را جابه‌جا نمی‌کند. آمادگی <code dir="ltr">09:00</code> شروع همان ساعت را مجاز می‌کند؛ <code dir="ltr">09:00:00.000001</code> آن را حذف می‌کند. گام می‌تواند از مدت کوتاه‌تر باشد و گزینه‌ها هم‌پوشانی داشته باشند؛ این‌ها پیشنهادهای جایگزین هستند.

بازه نیمه‌باز است و باید کامل در یک پنجره و یک تاریخ محلی جا بگیرد. پایان دقیق در ساعت بسته‌شدن یا <code dir="ltr">24:00</code> معتبر مجاز است؛ عبور از ناهار، اتصال دو پنجره مجاور یا مصرف زمان مثبت تاریخ بعد مجاز نیست. دو پنجره یک‌ساعته کنار هم، گزینه دوساعته نمی‌سازند.

مقدار days از تاریخ محلی آمادگی و با احتساب همان تاریخ، تعداد برچسب‌های تقویمی را تعیین می‌کند؛ تعداد روز کاری نیست. تعطیلی، تاریخ حذف‌شده یا فاصله اطلاع قبلی، محدوده را تمدید نمی‌کند. فهرست می‌تواند خالی باشد. خروجی به ترتیب زمان واقعی، بدون تکرار و حداکثر تا max_slots است.

## تغییر ساعت و نتیجه

شروع یا پایان ناموجود یا مبهم، و گزینه عبوری از تغییر offset، کنار گذاشته می‌شود. زمان محلی ناموجود به ساعت دیگری منتقل نمی‌شود. گزینه‌های روشن پیش و پس از تغییر همچنان می‌توانند باقی بمانند. ادامه شبانه به پنجره‌های روزانه تقسیم می‌شود؛ هر گزینه در تاریخ خودش می‌ماند.

نتیجه <code dir="ltr">DeliverySlotsResult</code> دارای <code dir="ltr">profile</code>، <code dir="ltr">timezone</code>، <code dir="ltr">readyAt</code>، <code dir="ltr">eligibleFromAt</code>، <code dir="ltr">requestedDays</code> و فهرست <code dir="ltr">slots</code> است. هر <code dir="ltr">DeliverySlot</code> دو لحظه تغییرناپذیر UTC با نام <code dir="ltr">startsAt</code> و <code dir="ltr">endsAt</code> دارد. <code dir="ltr">toArray()</code> علاوه بر زمان UTC، نمایش محلی هر بازه را در منطقه درخواست نگه می‌دارد؛ نوع‌ها و نام دقیق کلیدها را در [مرجع API](api-reference.md) ببینید.

ورودی نسبی، فقط تاریخ، ساعت ساده مبهم یا ناموجود پذیرفته نمی‌شود. [قواعد زمان و خطا](api-reference.md) و [ساعت کاری](working-hours.md) جزئیات مرزها را پوشش می‌دهند.
