# رفع اشکال

[English](../en/troubleshooting.md) · [همه راهنماها](README.md)

ابتدا نام پروفایل، منبع انتخابی، منطقه زمانی و ورودی دقیق محاسبه را مشخص کنید. از [تقویم کوچک شروع کار](getting-started.md) برای جداکردن مشکل تنظیمات برنامه از خود محاسبه استفاده کنید؛ داده اصلی را برای آزمایش پاک نکنید.

## یک بررسی کوچک و قابل تکرار

با تقویم شروع کار، وضعیت روز شنبه را همراه با دلیل ببینید:

<!-- example: explain-date -->

<div dir="ltr">

```php
use Zarbinco\LaravelWorkdays\Facades\Workday;

$info = Workday::profile('global')->explain('2026-11-07');
echo json_encode([
    'business' => $info->isBusinessDay,
    'weekend' => $info->isWeekend,
    'reason' => $info->reasons[0]->type,
], JSON_THROW_ON_ERROR), PHP_EOL;
```

</div>

<div dir="ltr">

```text
{"business":false,"weekend":true,"reason":"weekend"}
```

</div>

این خروجی، تعطیلی آخر هفته را نشان می‌دهد؛ همین روش را با تاریخ مسئله و پروفایل خودتان انجام دهید.

## نتیجه روز کاری با انتظار من فرق دارد

از <code dir="ltr">explain($date)-&gt;toArray()</code> استفاده کنید. آخر هفته، تعطیلی تکرارشونده و تعطیلی دقیق می‌توانند هم‌زمان وجود داشته باشند؛ روز کاری اضافه وضعیت نهایی را باز می‌کند، ولی دلیل‌های اولیه را حذف نمی‌کند. <code dir="ltr">isCalendarHoliday()</code> فقط تعطیلی تکرارشونده است و <code dir="ltr">isHoliday()</code> وضعیت نهایی غیرکاری. [روزهای کاری](business-days.md) تفاوت را با مثال نشان می‌دهد.

کلید تکرارشونده باید <code dir="ltr">MM-DD</code> و تاریخ دقیق <code dir="ltr">Y-m-d</code> میلادی معتبر باشد. نام تقویم درست <code dir="ltr">jalali</code> است. عنوان null، تعطیلی را حذف نمی‌کند. آخر هفته ایران همراه پکیج پنجشنبه و جمعه است؛ آن را مطابق سازمان تغییر دهید. تعطیلی قمری محاسبه‌شده ممکن است با اعلام رسمی محلی فرق کند؛ داده قطعی را با تاریخ دقیق ثبت کنید.

## روز کاری است، ولی ساعت باز پیدا نمی‌شود

کاری‌بودن تاریخ، وجود پنجره ساعت را تضمین نمی‌کند. ساعت هفتگی، ساعت اختصاصی خالی و روز صریح خالی در فصل را بررسی کنید. ساعت اختصاصی تعطیلی را باز نمی‌کند؛ روز کاری اضافه هم برای API زمانی به ساعت هفتگی یا ساعت جایگزین نیاز دارد. ادامه معتبر شیفت شب می‌تواند وارد روزی شود که خودش کاری نیست. [ساعت کاری](working-hours.md) ترتیب انتخاب را توضیح می‌دهد.

## جست‌وجو از حد می‌گذرد

پیام <code dir="ltr">Unable to resolve a business day</code> یا <code dir="ltr">WorkingTimeSearchException</code> را با پروفایل و حد گزارش‌شده بخوانید. مقدار <code dir="ltr">workdays.max_scan_days</code> حد ایمنی جست‌وجو است. تعطیلی‌های پیاپی، همه روزهای بسته یا نبود هم‌پوشانی انتقال می‌تواند حد را تمام کند. حد را فقط به‌اندازه نیاز عملیاتی و با هزینه جست‌وجو بالا ببرید؛ گزینه یک API اجازه افزایش حد سراسری را نمی‌دهد.

روز صفر و آخرین تاریخ هر API را با راهنمای همان قابلیت بررسی کنید. برنامه تحویل و SLA یک افق مشترک از ورودی اولیه دارند؛ هر مرحله و توقف حد تازه نمی‌گیرد. days بازه‌ها تعداد تاریخ تقویمی است؛ count تکرار تعداد دوره، حتی دوره ردشده، است. اختلاف روز با جست‌وجوی زمان و حد آن یکی نیست.

## منبع Database در دسترس نیست

مقدار driver باید دقیقاً config یا database باشد. در حالت Database، اتصال انتخابی، سه جدول نسخه تعریف و انتشار اولیه صریح را بررسی کنید. migration جدول قدیمی تعطیلی کافی نیست. پروفایل مفقود از Config یا تنظیم آغازین ایران گرفته نمی‌شود. خرابی منبع با <code dir="ltr">DefinitionSourceException</code> گزارش می‌شود، حتی در collect گروهی یا مقایسه snapshot.

در Config، پکیج نباید به Database نیاز داشته باشد. کلیدهای عملیاتی قدیمی ریشه و <code dir="ltr">storage.driver</code> را به ساختار [تنظیمات فعلی](configuration.md) منتقل کنید. برای راه‌اندازی جدید از [راهنمای مستقل Database](database.md) استفاده کنید؛ بازسازی کامل جداول برنامه راه‌حل عمومی این خطا نیست.

## انتشار با تعارض رد شد یا تغییر جدید دیده نمی‌شود

نسخه‌ای را که هنگام ویرایش خوانده‌اید با <code dir="ltr">expectedRevisionId</code> بفرستید. تعارض یعنی شخص یا فرایند دیگری زودتر منتشر کرده است؛ آخرین سند را بخوانید و تغییرها را ادغام کنید. null فقط مقداردهی اولیه منبع بدون نسخه است. انتشار هم‌ارز می‌تواند نسخه تازه نسازد.

محاسبه‌گر نگه‌داشته‌شده، نمای قدیمی خود را حفظ می‌کند. برای دیدن انتشار یا تغییر Config جدید، محاسبه‌گر تازه بگیرید. تغییر روش روی همان شیء آن را تازه نمی‌کند. برای حفظ عمدی شواهد قابل ذخیره، از [snapshot برآورد](snapshots.md) استفاده کنید.

## ورود تقویم ایران رد می‌شود

Config فقط dry-run خود داده را می‌پذیرد؛ نوشتن نیازمند Database آماده و پروفایل موجود است. فایل محلی سال، تاریخ‌ها و تطابق شمسی و میلادی باید معتبر باشند. force فقط بازنویسی مقدار تعطیلی متعارض را مجاز می‌کند، نه نسخه قدیمی، داده نادرست یا بازفعال‌شدن ناخواسته تعطیلی پاک‌شده والد. سیاست ارث‌بری مقصد را پیش از تلاش دوباره بررسی کنید. داده رسمی سالانه خودکار دریافت یا همراه پکیج نصب نشده است.

## اختلاف ثانیه، مرز بسته‌شدن یا تغییر ساعت

بودجه دقیقه صحیح است، اما مصرف ثانیه و میکروثانیه را حفظ می‌کند. اختلاف دقیقه مجموع هم‌پوشانی را فقط یک بار قطع می‌کند. پایان پنجره خارج از عضویت است؛ زمان کاری قبلی می‌تواند یک میکروثانیه قبل از پایان باشد. work صفر در برنامه به زمان باز می‌رود، ولی جمع صفر در هسته ورودی را حفظ می‌کند.

منطقه IANA واقعی تقویم را بدهید. برای ساعت تکراری offset صریح یا شیء تاریخ با لحظه قطعی استفاده کنید؛ ساعت ناموجود را با جابه‌جایی بی‌صدا اصلاح نکنید. ساعت تنظیم‌شده ناموجود یا مبهم می‌تواند خطای تقویم بدهد. بازه تحویل نزدیک تغییر offset عمداً بعضی گزینه‌ها را کنار می‌گذارد. [مرجع زمان](api-reference.md) تفاوت parserها را مشخص می‌کند.

## snapshot بازیابی نمی‌شود

داده JSON، فیلدها، checksum و محدودیت حجم را بررسی کنید. معنای محاسبه پشتیبانی‌نشده با تغییر شماره نسخه یا hash قابل مهاجرت نیست. snapshot را از ورودی اصلی دوباره بسازید یا داده قدیمی را فقط برای بررسی تاریخی جدا نگه دارید. تغییر tzdb با خرابی checksum یکسان نیست؛ [قرارداد بازیابی](snapshots.md) حدود بازاجرای تاریخی را توضیح می‌دهد.

## ماکرو یا قاعده فرم کار نمی‌کند

ثبت ماکرو و تداخل با نام موجود را بررسی کنید؛ نام دارای پیشوند <code dir="ltr">workday</code> روشن‌تر است. پروفایل باید موجود باشد و قاعده businessTime ساعت کاری لازم دارد. شرط نسبی from حذف‌شده از امروز استفاده می‌کند؛ برای نتیجه قابل تکرار تاریخ را صریح بدهید. جزئیات در [اتصال به لاراول](laravel-integration.md) است.

برای گزارش مشکل، کوچک‌ترین تعریف لازم، ورودی دقیق، نسخه‌های PHP و کتابخانه‌ها، منطقه زمانی و پیام کامل خطا را ارائه کنید. اطلاعات اتصال، داده مشتری و سایر اطلاعات خصوصی را از نمونه حذف کنید. [راهنمای مشارکت](../../CONTRIBUTING.md) روش اجرای تست‌های مخزن را دارد.
